# 微信群内激活

先把机器人微信号拉入目标群。绑定管理员在群里选择微信原生的 @二狗，随后发送一条指令。

| 指令 | 对本群的作用 |
| --- | --- |
| 激活本群 | 开始接收指令和点名回复，重复发送会告知已激活 |
| 绑定状态 | 查看当前群是否已激活 |
| 停用本群 | 暂停群内服务，取消尚未投递的普通回复，保留积分和游戏数据 |

群按微信的稳定群 ID 区分，群名可相同。停用后可以在原群再次激活。语音、成员通知和模型凭据等逐群单独配置。后台解绑或撤销的接入由后台核对恢复。

## 管理绑定权限

绑定管理员名单按机器人微信账号保存，与智能对话管理员分别授权。Linux 上可用服务账号在部署目录运行下列命令，将最后一项替换成实际微信稳定 ID。

```sh
python3 -m deploy.group_workers binding-admin grant '微信稳定ID'
python3 -m deploy.group_workers binding-admin revoke '微信稳定ID'
```

账号只维护一条入站事件流及一个持久游标。私聊直接跳过。未绑定群的实时事件在检查管理指令时可能需要向本机微信插件读取消息详情，普通消息不进入机器人收件箱、模型或游戏。绑定回执只发到指令发起群。

新增绑定指令在 `ergou/group_binding.py` 登记指令和群状态变化，沿用微信身份、真实提及、消息时间及跨群管理员检查。业务功能继续使用群 ID 和绑定版本，接收与投递共用 `deploy/group_stream.py` 的有效群查询。

已领养的机器人由主人管理跨群绑定。首任主人及此后的转移、群主授权和管理员角色见《群主授权》。本页的独立绑定名单只适用于尚未领养的旧节点。
