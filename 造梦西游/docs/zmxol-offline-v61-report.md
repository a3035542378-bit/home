## 点券与事务

每个本地档首次进入商城赠200万测试点券，明确为OFFLINE_COMPAT。已有198赠券只补差1999802一次，保留消费；本轮197补为1999999。达到配置赠券总额后不再补，不因消费后余额低于200万而重复赠送。不连接官方充值、支付、运营服务器，不修改远程资产。

cmd7/REQUEST_ITEM_LIST仅处理已核rid10001请求，并绑定实际队列request身份。列表返回原消费者所需point/item/stone/petitem/fashion/hotsale；不是全部请求统一成功。

cmd9/REQUEST_PURCHASE仅接管白名单、rid10001/service1/category0、整数数量1–99。校验余额、快照、容量、旧请求；原生发奖后校验完整袋快照变化和原Player余额，物品、点券及`_offline_shop`消费收据进入同一次原子写（temp→fsync→rename→目录fsync），成功后放行结果通知。重复响应在原发奖前阻断；旧快照不重新扣费。收据为本地私有字段，不发送到原角色响应。

现有限制：无旧实验CP字段的堆叠暂限99件；单档最多1000笔消费记录；未重建分页账本。新物品使用原生A2/A4序列化，不补造CP字段。物理断电、设备文件系统故障和真实重复网络包尚未完成设备注入验收。

异常后锁存储、丢弃成功通知，要求重新启动；成功反馈前的异常不把半成品写进正常存档。目录fsync失败等提交结果不明确场景仍需专项验收，不承诺所有设备故障已经排除。
